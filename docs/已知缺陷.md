## 批次 1（已修复，2026-09-11 · commit `f0f54a2`）

### F-01 恢复配额全局累积 🔴

**症状**：`max_recovery_attempts=2` 被实现成**整场比赛总配额**。实测第 3 次**互不相关的瞬时故障**（即便前两次都恢复成功）就直接 `FAILED` 永久停机。

**根因**：`recovery_attempts` 仅在 `__init__` 归零，任何成功推进路径都不重置。

**影响**：赛题流程十几步硬件动作 + 5 小时综合实践，三次抖动（串口、遮挡、超时）叠加即停死。把异常恢复从「保险」变成「倒计时炸弹」。

**修复**：引入 `_PROGRESS_EVENTS`，任务实质推进（确认事件到达）即归还配额；恢复类事件刻意排除，防止 `recovery_done` 刷屏绕过限制。两套状态机同步（此前各错一遍）。

**验证**：修复后 5 次瞬时故障全部存活；连续失败仍能正确耗尽配额。

### F-03 S0 自检阶段超时豁免 🟠

**症状**：相机在 S0 阶段失效 → `tick()` 直接返回空 → 运行循环永久空转，无恢复、无日志。

**修复**：移除 `S0_INIT` 豁免；S0 独立短超时（默认 3000ms，纯 PING 级交互不应沿用全局 5000ms）。

### F-04 `safe_stop` 被悬挂 pending 阻塞 🟠

**症状**：协议同一时刻只允许一条未完成命令；F407 已 ACK 却迟迟不 DONE 时，`safe_stop` 被 `send_command` 拒绝，原逻辑既不清理也不重试 → **F407 收不到任何停止指令**。

**修复**：`safe_stop` 发送前抢占式清障；失败时落盘独立 `safe_stop_failed` 事件（原先静默，丢失比赛复盘证据）。

## 批次 2（待办，与硬件确认表并行）

### F-02 `sensor_provider` 是空壳 🔴

**症状**：全仓库仅 `tests/test_实机运行时.py:120` 一处赋值，**生产代码从不设置**。文档宣称「钩子已就绪，接上即可」，实际没有创建/注入路径。

**后果**：ToF、限位、抓取确认在实机上永远读到静态配置值，安全门形同虚设。审查报告 P0-2 标注「已修」实为「改判」——从「误拦截」换成「完全不检查」，**并未根治**。

**前置**：F407 确认表 ④ —— 抓取状态能否上报。三选一：

| 方案 | 实现 | 代价 |
|---|---|---|
| A. F407 遥测帧 | 新增 `MessageType.TELEMETRY`，`protocol.receive` 解析后写 sensors | 需改固件，最可靠 |
| B. GPIO | `lgpio`/`RPi.GPIO` 读限位/抓取引脚 | 需接线，独立于串口 |
| C. 视觉确认 | 抓取后拍照比对有无物料 | 无硬件依赖，可靠性低 |

**落地要点**：`config/实机配置.json` 新增 `sensor_source`（默认 `"none"` **保持现有行为**）；`tools/启动检查.py` 扩展 `competition` 门禁（`sensor_source=="none"` → error）。

### F-05 `TASK_QR` 校验恒真 🟡

`mission/扫码读取.py:58-64` 只对 `CODE128` 做白名单校验，`TASK_QR` 任何非空字符串都 `valid=True`。脏数据要到 `parse_task_qr` 才失败，使 `scan_retries` 统计的是「JSON 解析失败」而非「扫码质量失败」，语义失真。

**修复方向**：轻量预校验（非空 + 首字符 `{` + 长度上限），**不做**完整 JSON 解析（保持分层）。

### F-06 `assemble_material` 不校验批次 🟡

`_require_current` 只按 `material_id` 查，不校验 batch 归属；S4 分支理论上可拿到第一批物料。

**修复方向**：`_require_current` 增 `expected_batch` 参数，S4 传 `"second"`。

### F-07 视觉任务状态机死代码 🟡（**需决策**）

`mission/视觉任务状态机.py`（150 行）**生产零引用**：实机走的是 `LiveRuntime._advance_fine_localization` 里另写的一套简化逻辑。

| 选项 | 说明 | 风险 |
|---|---|---|
| A. 接入 | 用 `TaskStateMachine` 替换简化逻辑 | 改动大，需重测整条实机抓放链 |
| B. 归档 | 移入 `archive/` 并注明待用（对齐 P2-6 处理 `BarcodeWorldMapper`） | 丢失已验证逻辑可达性 |
| C. 保留 | 加注释说明为「单目标模式预留」 | 技术债持续 |

**建议先 B**：`_advance_fine_localization` 已在实机路径且经测试覆盖，风险更低；实机联调后再评估 A。

### F-08 仿真测不出安全拦截 🟡

`VirtualSensors.grasp_confirmed` 默认 `None`，实机配置也是 `null` —— 两边都「跳过检查」，所以**仿真永远测不出装配拦截问题**，安全门在仿真中得不到验证。

**修复方向**：`create_simulation_runtime` 显式传 `grasp_confirmed=False`，覆盖拦截路径。

### F-09 恢复行为无结构化观测 🟡

目前故障复盘只能翻 jsonl。`TestSession` 应增 `recovery_attempts` / `state_durations` 进 `summary.json`，恢复事件带 `attempt` / `resume_state`。

> 与 F-01 配合使用：配额放宽后，需靠累计恢复次数在复盘中识别「频繁抖动」的真问题，避免放宽掩盖故障。
