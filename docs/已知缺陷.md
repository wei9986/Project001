## 批次 1（已修复，2026-09-11 · commit `f0f54a2`）

### F-01 恢复配额全局累积 🔴

**症状**：`max_recovery_attempts=2` 被实现成**整场比赛总配额**。实测第 3 次**互不相关的瞬时故障**（即便前两次都恢复成功）就直接 `FAILED` 永久停机。

**根因**：`recovery_attempts` 仅在 `__init__` 归零，任何成功推进路径都不重置。

**影响**：赛题流程十几步硬件动作 + 5 小时综合实践，三次抖动（串口、遮挡、超时）叠加即停死。把异常恢复从「保险」变成「倒计时炸弹」。

**修复**：引入 `_PROGRESS_EVENTS`，任务实质推进（确认事件到达）即归还配额；恢复类事件刻意排除，防止 `recovery_done` 刷屏绕过限制。两套状态机同步（此前各错一遍）。

**验证**：修复后 5 次瞬时故障全部存活；连续失败仍能正确耗尽配额。

### F-03 S0 自检阶段超时豁免 🟠

**症状**：相机在 S0 阶段失效 → `tick()` 直接返回空 → 运行循环永久空转，无恢复、无日志。

**修复**：移除 `S0_INIT` 豁免；S0 独立短超时（默认 3000ms，纯 PING 级交互不应沿用全局 5000ms）。

### F-04 `safe_stop` 被悬挂 pending 阻塞 🟠

**症状**：协议同一时刻只允许一条未完成命令；F407 已 ACK 却迟迟不 DONE 时，`safe_stop` 被 `send_command` 拒绝，原逻辑既不清理也不重试 → **F407 收不到任何停止指令**。

**修复**：`safe_stop` 发送前抢占式清障；失败时落盘独立 `safe_stop_failed` 事件（原先静默，丢失比赛复盘证据）。

## 批次 2（已修复，2026-09-11）

### F-05 `TASK_QR` 校验恒真 🟡

**症状**：`validate_scan` 只对 `CODE128` 做白名单校验，`TASK_QR` 任何非空字符串都 `valid=True`。脏数据要到 `parse_task_qr` 才失败，使 `scan_retries` 统计的是「JSON 解析失败」而非「扫码质量失败」，语义失真。

**修复**：新增 `MAX_TASK_QR_LENGTH=4096`；`TASK_QR` 做轻量预校验（非空 + JSON 对象前缀 `{` + 长度上限），**不在此解析 JSON**（保持分层，完整结构与字段校验仍由 `parse_task_qr` 负责）。

**测试**：`test_task_qr_rejects_non_json_prefix` / `test_task_qr_rejects_empty_and_oversized` / `test_code128_validation_unchanged`

### F-06 `assemble_material` 不校验批次 🟡

**症状**：`_require_current` 只按 `material_id` 查，不校验 batch 归属，S4 理论上可装配到第一批物料。

**修复**：`_require_current(expected_batch=...)` 新增批次校验；S4 的两个分支（`material_loaded` / `assembly_done`）传 `"second"`。缺省不检查批次，保持 S2/S3 既有语义不变。顺带把 `next(...)` 的 StopIteration 改为显式 `RuntimeError`，避免物料不在计划中时抛出令人困惑的异常。

**测试**：`test_assemble_material_belongs_to_second_batch` / `test_require_current_rejects_wrong_batch` / `test_assemble_rejects_first_batch_material`

### F-08 仿真测不出安全拦截 🟡

**症状**：仿真与实机 `grasp_confirmed` 都是 `None` → 安全门恒被跳过 → **「装配拦截」这条关键安全路径在仿真里完全得不到验证**。

**修复**：
1. `create_simulation_runtime` 显式传 `grasp_confirmed=True`，让安全门真正参与判定。
2. **顺带修一个接口不一致**：`VirtualSensors` 缺少实机 `LiveSensors` 已有的 `update()` 方法，导致仿真与实机的传感器刷新路径代码不同构。现补齐，且校验规则完全对齐（非法类型立即报错），避免仿真接受实机会拒绝的脏值。

**测试**：`test_simulation_runtime_has_active_grasp_sensor` / `test_simulation_safety_gate_can_block`

### F-09 恢复行为无结构化观测 🟡

**症状**：故障复盘只能翻 jsonl 人工数。与 F-01 叠加后风险更大——**配额放宽后，若没有累积恢复次数指标，"频繁抖动"的真问题会被掩盖**。

**修复**：`TestSession` 新增 `record_recovery(attempt, resume_state, reason)` 与 `record_state(state, elapsed_ms)`；`summary.json` 固定输出 `recovery_events` / `recovery_by_reason` / `state_time_ms`（缺省为 `0`/`{}`，避免下游 KeyError）。`LiveRuntime._execute` 在产出 `recover` 动作时自动记录。

**测试**：`test_summary_records_recovery_metrics` / `test_summary_recovery_metrics_default_zero` / `test_summary_is_json_serializable`
