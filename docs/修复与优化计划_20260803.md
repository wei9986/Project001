## 2. 分项修复执行方案（P0~P3，时间无关，优先级驱动）

### 2.1 P0 —— 阻塞级（阶段 S1，8/10-8/20 完成）

#### P0-1 恢复机制：恢复成功后重发被中断动作
- **根因**：状态机只记 `resume_state`，不记被打断的硬件动作；`recovery_done` 只输出无映射的 `resume_state` 动作。
- **修复设计**：
  1. `MissionStateMachine` 加 `in_flight: Optional[MissionAction]`；凡输出会被 DONE 确认的硬件动作（`self_test`/`load_first_material`/`place_ring`/`load_second_material`/`assemble_material`/`return_home`）记录之，对应确认事件（`self_test_ok`/`material_loaded`/`ring_placed`/`assembly_done`/`home_confirmed`）清空。
  2. `_recover` 保持 `in_flight`；`recovery_done` → `_transition(resume_state)` 后，若 `in_flight` 非空则返回 `[in_flight]` 重发。
  3. 连带 P1-2：`_recover` 仅 `self.state != RECOVERY` 时存 `resume_state`；RECOVERY 态加超时（tick 不再排除），超时耗尽即 FAILED。
- **文件**：`mission/任务状态机.py`、`app/实机运行.py`、`app/运行循环.py`。
- **测试（先红后绿）**：`test_recovery_reissues_interrupted_action`、`test_recovery_second_failure_does_not_override_resume_state`、`test_recovery_state_times_out`。
- **验收**：实机模拟 RECOVER 先 FAIL 后成功 + 中途拔线，任务能续跑而非 FAILED；离线评测 normal 场景注入一次故障后仍 complete。

#### P0-2 实机安全传感器接入数据源；未接入前不「一票否决」
- **修复设计**：
  1. `LiveSensors` 加 `update(**kwargs)`，运行循环每帧调用；语义对齐 ToF：`grasp_confirmed: Optional[bool]`——`None` 未接入→跳过检查，`False` 已接入未确认→拦截。`实机配置.json` 默认 `null`。
  2. `SafetyMonitor.check`：仅 `grasp_confirmed is False` 才拦 `assemble_material`。
  3. 数据源三选一：F407 遥测 / GPIO / 视觉抓取确认（按确认表④定）。
  4. 反向门：ToF/限位未接数据源时 `vision_config_loaded` 日志明确告警，不静默。
- **文件**：`app/实机设备.py`、`app/安全监控.py`、`app/实机运行.py`、`config/实机配置.json`、`tests/test_实机模块.py`。
- **测试**：`test_assemble_allowed_when_grasp_sensor_absent`、`test_assemble_blocked_when_grasp_false`、`test_live_sensors_update_interface`。
- **验收**：实机含第二批任务能过 S4；接入真实抓取信号后未抓取拦截、已抓取放行。

## 3. 增强项（对齐《深度开发指南》推荐顺序，阶段 S2~S4）

### 3.1 真实数据回放（阶段 S2 起，硬件轨同步采集）
- `data/replay/` 存真实帧（正常/暗光/强光/反光/旋转/遮挡/多目标/相机振动），`tools/仿真验证.py` 支持按回放集测颜色/站点/精定位的检测率、漏检、误检、ID 切换、P95 耗时。
- 验收：每类 ≥30 帧，报告入库；调参改动后能回放比对。

### 3.2 虚拟 STM32 故障注入增强（阶段 S3）
- `protocol/协议仿真.py` 补：延迟响应、重复 ACK、错误序号、执行中断、控制器复位、心跳停止、随机丢包、CRC 损坏。
- 每种故障记录注入条件/预期状态/错误码/恢复动作（深度开发指南 §12）。

### 3.3 YOLO 研究轨（go/no-go 决策，不默认排期）
- **go 条件**（M2 决策）：赛题判分需要形状/实例区分（环码、料型），且 HSV 无法满足。
- 若 go：用 `data/shapes_dataset`（已有 3 色 YOLO 数据集）训练 `yolo11n.pt`，接入作二级确认（HSV 初筛 → YOLO 精确认），目标 Pi 上推理 ≤30ms。
- 若 no：沿用 HSV，不启动（避免挤占实机闭环时间）。

### 3.4 安全状态机完善（阶段 S3）
- 按 `正常 → 警告 → 恢复 → 安全停止 → 故障锁定` 分层；高优先级故障：限位、ToF 过近、串口断开、抓取失败、相机失联、坐标跳变、状态超时。安全停止幂等、记录原因、禁止普通动作、等明确复位（深度开发指南 §13）。

### 3.5 配置版本与类型校验（阶段 S3）
- 配置 JSON 加 `schema_version`；启动检查按 `config/*.json` 全覆盖类型/范围/引用校验（合并 P2-15）。

### 3.6 性能监控与树莓派部署（阶段 S3~S4）
- Pi 上实测：每色耗时、主循环周期、FPS、掉帧率、欠压（vcgencmd 降频 1s）；P95 延迟进 `summary.json`。
- 性能优化优先级：ROI → 降分辨率 → undistort 条件化（P3-1）→ 匹配限幅（P1-5）→ pipeline 测时定位热点。

## 4. Track B：硬件/实机执行方案
