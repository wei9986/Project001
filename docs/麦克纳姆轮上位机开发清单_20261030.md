# 麦克纳姆轮上位机开发清单

日期：2026-10-30。适用：树莓派视觉上位机 + F407 + 麦克纳姆轮底盘，智能搬运赛道。

## 方案与范围

首版采用固定路线、下位机编码器/IMU运动闭环、工位附近视觉纠偏、运动方向测距防撞。不以 SLAM、全场视觉里程计或复杂动态绕障为首版前提。AprilTag 可用于开发测试；正式场地能否添加标记尚未确认，比赛版应使用经允许的场地特征。

上位机负责任务解析、任务调度、路线段管理、视觉定位与纠偏、反馈处理、状态显示和日志；F407 负责四轮运动学、编码器、电机 PID、IMU 航向控制、即时停车和硬件执行。本文描述上位机待开发范围，不代表下位机已有这些功能。

P0：后续开发前提；P1：最小参赛闭环；P2：增强与扩展。当前没有充分实机数据，不以百分比估计完成度。

## 开发项与验收标准

| 编号 | 优先级 | 开发项 | 当前基础与缺口 | 上位机交付及验收标准 |
|---|---|---|---|---|
| U01 | P0 | 统一正式任务解析 | `tools/task_color_test.py` 已解析四组三位码；`mission/扫码读取.py` 的正式任务解析仍要求 JSON | 将四组解析放入共享任务模块，工具与 live 共用。第1/3组解析颜色顺序，第2/4组解析对应位置；保留原始任务码；位置1/2/3不与六条精度环混为一谈。验证长度、非法符号、位置排列、两批颜色一致性等官方约束，禁止静默忽略任何一组 |
| U02 | P0 | 重构比赛任务流程 | 现有状态机主要为单件取料后放环、第二批装配，没有完整工位搬运流程 | 显式实现出发→扫码→第一批逐件取上车→粗加工逐件放下→按序取回→暂存区逐件放下→第二批同流程并在暂存区同色码垛→回启停区。每一步绑定批次、物料、车载槽位、目的位置和完成条件；第二批暂存位置按第一批同色物料记录匹配 |
| U03 | P0 | 修复并冻结通信协议 | 有 PackUnpack 10字节编解码、ACK/DONE/FAIL框架；JSON载荷超长，序号高位截断，模块ID配置未接入 | 采用明确的二进制字段；协议文档规定命令、单位、符号、坐标系、数据范围、字节序、填充、分帧和消息关联。修复序号与模块ID；验证高位字节、分包粘包、坏包、旧响应、重试去重、停止优先级；与F407共享测试向量 |
| U04 | P0 | 建立控制器反馈与状态快照 | 有传感器对象、`sensor_provider`扩展口和基本应答；缺生产反馈适配 | 解析姿态、运动状态、各方向距离、限位、抓取/放置结果、故障、复位信息；每项带接收时刻和有效期。数据失效或控制器复位时禁止按旧状态推进任务；ACK不能作为物理完成证据 |
| U05 | P1 | 固定路线执行器 | 有站点配置和运动命令枚举；站点坐标为占位，没有路线执行器 | 配置起点1/2及工位间路线，支持前后、横移、旋转、等待、视觉对准；顺序执行、检查到位、超时停止、禁止重复下发。记录当前路线段及恢复点。先在离线反馈仿真中走通，再测底盘 |
| U06 | P1 | 坐标与航向接口 | 有相机标定、像素到平面坐标和Tag姿态估计 | 明确图像、相机、车体、场地坐标系及单位；完成内参、相机安装变换和地面/抓取平面标定。接收F407里程计与IMU航向；有效视觉观测才校正位姿。用已知点验证误差；横移打滑不能仅靠编码器消除 |
| U07 | P1 | 官方颜色与转盘目标识别 | 有HSV追踪、锁定、稳定性工具；现有阈值不覆盖黑色和浅蓝 | 按官方映射覆盖全部指定颜色；补齐真实阈值及反光/阴影测试。动态目标不直接套用静止目标门槛；处理6～10秒/转、正反转、停位误差、目标丢失和坐标过期。只输出当前有效目标与采样时间 |
| U08 | P1 | 工位与放置位置定位 | 有AprilTag模块，没有经验证的比赛场地视觉方案 | 识别允许使用的车道/圆环/位置数字等特征，区分放置位置1/2/3与同心环精度等级；输出工位、中心偏差和置信度。错误工位、未知位置、无目标时不执行放料；不能假定允许贴Tag |
| U09 | P1 | 麦轮到站视觉纠偏 | 有精定位采样，无底盘视觉纠偏执行器 | 根据车体坐标偏差下发有界的小距离前后/横移修正，每次执行后重新观察；限制速度、步长、总次数和超时；达到经实测确定的位置/角度阈值并连续稳定后才放行 |
| U10 | P1 | 底盘旋转对准 | 有`yaw_deg`字段及姿态接口，没有旋转闭环调度 | 下发目标航向，读取F407执行结果；处理±180度跨界和最短转向，必要时用有效视觉方向修正。对称圆环中心不能单独提供航向；物料/夹爪旋转姿态另列执行接口，不与底盘旋转混用 |
| U11 | P1 | 按运动方向防撞与故障管理 | 有ToF动作前门禁，缺连续运动监控及多方向反馈 | 前后/横移检查对应方向传感器和有效期，协调减速、停车、等待和终止；停车阈值按速度、车体外形和制动试验确定；F407独立执行即时停车。无绕行空间或车道依据时不自动绕行。停车功能不等同完整自主绕障 |
| U12 | P1 | 抓取、载运、放置及码垛确认 | 有动作映射与物料状态，没有完整实机反馈链路 | 使用关联到当前动作的硬件结果更新车载库存和场地库存；确认取上车后再取下一件；抓空、掉落、放置失败不能算完成。维护第一批同色物料位置，第二批按同色堆叠；码垛高度及执行参数由机械实测提供 |
| U13 | P1 | 比赛入口与显示 | 有桌面启动和视觉测试窗口，仍以空格确认视觉项 | 增加实体启动事件适配和比赛模式，启动后不依赖键鼠推进；扫码后持续显示完整原始任务码、抓取/放置进度和故障。验证机器人上部显示装置实物字高≥12mm及可读性；桌面脚本不能替代实体按钮 |
| U14 | P1 | 比赛约束与故障终止 | 有状态超时/恢复框架，没有运动反馈监控 | 根据正式规则解释定义15秒无移动观测口径，并用反馈验证；增加恢复总时间预算，防止持续等待。路线考虑整车外廓和车道边界；越界监测需有效边界与位姿依据，不能凭空保证。断连、复位、感知失效等触发确定的停止策略 |
| U15 | P1 | 集成测试、日志与部署 | 有unittest、JSONL、回放与部署工具；历史全量回归未通过 | 修复旧协议测试和实际功能失败，更新旧两组任务码示例/测试；记录动作ID、批次、槽位、坐标、传感器时间、结果和故障。执行两起点、不同任务、两批完整流程、异常注入和Pi长时间运行；重新打包，旧ZIP不视为本轮更新 |
| U16 | P2 | 无线状态接口与扩展识别 | 没有比赛无线应用链路及通用形状/OCR能力 | 按正式要求确认无线用途，必要时增加只读状态上传；与主控制链路隔离。按实际赛题补形状、数字/文字识别；环位数字识别若被选为定位依据则属于U08优先实现 |

## 建议开发顺序与阶段出口

1. **任务和通信基础（U01～U04）**：正式入口能读取四组任务码；共享二进制协议与F407参考报文一致；两批任务计划覆盖全部工位操作；反馈失效和重复响应测试通过。
2. **底盘联调（U05、U06、U10、U11）**：直行、横移、旋转均可下发并获取可信结果；移动方向防撞和失联停车通过；再执行工位间固定路线。
3. **视觉与作业（U07～U09、U12）**：真实物料、圆环和地面标定完成；抓取前纠偏与工位识别通过；逐步验证一件、整批、两批码垛。
4. **比赛集成（U13～U15）**：实体一键启动后无人干预完成扫码、两批搬运码垛和返回；任务码显示符合实物要求；保存完整验收日志。
5. **按赛题扩展（U16及主动绕障）**：只有在实际需求与允许车道范围明确后增加无线功能、动态绕障及决赛识别适配。

## 需要下位机与机械组提供的输入

这些属于接口依赖，不是要求树莓派实现电机控制。

- 底盘四轮布局、轮径、轮间距、编码器方向及分辨率，最大平移/横移/旋转速度，制动距离，车体含载物外廓。
- F407支持的运动动作、坐标约定、航向约定、反馈频率、动作完成判据、去重规则、复位识别及通信失联停车行为。
- 各方向测距传感器型号、安装位置和有效范围；IMU、编码器、限位、夹爪及放置反馈字段。
- 相机型号、数量、安装位置和机械臂运动时相机是否移动；各工位高度、夹爪中心、车载槽位和码垛参数。
- 真实场地尺寸、两出发位置、车道范围、位置1/2/3布局，以及允许使用的定位标记。未测量数值不得作为实机默认值。

## 已知结论修正

- 四组任务码已在视觉测试解析器接入，不表示正式live入口和完整状态机已适配。
- 示例`452+321+254+312`第一批颜色顺序为4、5、2（绿、黑、黄）；第二批为2、5、4（黄、黑、绿）。此前答复把第一批写成5、4、2有误。
- PDF中圆环内位置数字1/2/3与同心精度环1～6是不同概念；此前对照文档将它们混用，不能按“放置位置1～6”开发。
- 不能假定现场允许新增AprilTag；不能把车头旋转对准等同于物料或夹爪旋转定位。
- 本清单依据代码检查和提供的任务讲解PDF整理；历史测试成绩不是本次重新运行的测试结果。
