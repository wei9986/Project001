# 智能搬运赛道对照检查

依据：`intelligence20260617.pdf` 中“2027 年中国大学生工创实践与创新能力大赛——智能+工程创新赛道竞赛命题解析”。本文只把 PDF 作为赛道规则参考，具体比赛以正式发布的赛题、现场裁判解释和决赛规则为准。

## 结论

当前上位机已经具备颜色视觉测试、任务码读取框架、目标跟踪、AprilTag 站点识别、任务状态机、串口传输接口和日志记录能力。当前默认启动脚本仍是“相机 + 任务码 + 颜色目标人工确认”的开发测试流程，不是可直接参赛的智能搬运完整闭环。

全量自动化测试在当前环境曾出现 8 项失败、4 项错误；颜色任务测试、目标选择和目标质量专项测试通过。通信协议迁移到 PackUnpack 固定帧后，动作载荷与应用层适配仍需单独修复和联调。

## 规则要求与上位机现状

| 规则要求 | 当前代码对应能力 | 状态 | 说明 |
|---|---|---|---|
| 自主定位 | AprilTag 站点检测、相机标定和精定位模块 | 部分具备，未完成实机验证 | `vision/站点定位.py`、`vision/相机标定.py`、`vision/精定位.py` 已存在；`config/实机配置.json` 当前 `calibration=null`，精定位关闭 |
| 自主移动 | 任务状态机能产生导航动作名 | 缺失/未接入 | 没有底盘里程计、速度闭环、位置反馈或运动控制实现；动作最终依赖 F407，但真实动作协议未完成闭环 |
| 避障 | 安全监控有 ToF 字段和距离门禁 | 缺失实机数据源 | `LiveSensors` 目前主要从配置初始化，未形成运行时 ToF/障碍物更新链路；没有障碍物地图或避障规划 |
| 读取二维码 | OpenCV 二维码读取、外接扫码器解析 | 部分具备，需现场验证 | 支持任务二维码和 Code128 接口；需验证二维码板距离、角度、转盘背景、反光和 3 分钟调试限制下的识别率 |
| 读取条码 | `ExternalScannerParser`、`BarcodeWorldMapper` | 接口具备，主流程未接入 | 条码坐标映射在 `config/任务配置.json` 中为占位值，`BarcodeWorldMapper` 未接入完整实机路径 |
| 读取图形、数字、文字 | 任务码中的数字可解析 | 缺失 | 没有通用文字 OCR、图形分类或数字目标识别链路 |
| 读取颜色 | HSV 多目标追踪、颜色任务测试 | 部分具备 | 当前生产配置和任务解析主要支持红、绿、蓝；规则初赛要求六色：红1、黄2、蓝3、绿4、黑5、浅蓝6 |
| 无线通信 | 当前为串口传输 | 缺失/待定 | 代码使用 USB/TTL 串口与 F407 通信，没有无线链路；需确认赛方“无线通信”是否要求机器人必须具备无线功能，以及用途和接口 |
| 识别物料位置 | 像素中心、精定位、AprilTag 站点 | 部分具备 | 尚未形成转盘目标到机器人/世界坐标的稳定映射；相机标定和场地坐标需要实测 |
| 识别物料形状 | 轮廓面积、颜色目标筛选 | 缺失 | 没有针对回转体/未知决赛形状的形状分类；决赛形状变化需重新设计识别策略 |
| 物料抓取 | 有 `PICK`、`GRASP`、`VERIFY_GRASP` 动作映射 | 接口具备，闭环缺失 | 没有真实夹爪/抓取确认数据源；实机配置中的 `grasp_confirmed` 不是运行时传感器 |
| 物料载运 | 任务状态机有批次和物料状态 | 接口具备，未验证 | 没有底盘运动和载荷状态反馈；必须验证一次只取一件、物料不掉落 |
| 旋转定位 | 动作枚举有 `SET_POSE`、`MOVE_REL` 等 | 未接入 | 没有明确的旋转角度反馈、环号定位和落料姿态控制闭环 |
| 路径规划 | 任务顺序可生成动作 | 缺失 | 没有场地图、车道约束、动态转盘/障碍物路径规划；规则要求机器人离开出发区后在行车区域行走 |
| 任务完成统计 | JSONL 日志和测试汇总工具 | 部分具备 | 能记录视觉确认和动作事件；尚未形成比赛要求的抓取/放置信息显示、正确率和有效得分统计 |
| 上部静态任务码显示 | 软件能读取任务码 | 缺失 | PDF 要求机器人上部醒目位置持续显示任务码，字高不小于 12 mm；当前没有显示器驱动、内容同步和可视性验证 |
| 两批任务 | `TaskInstruction`、`TaskPlan` 有 first/second batch | 部分具备 | 当前 `config/task_color_test.json` 是 2 组视觉测试配置；正式规则任务码是 4 组三位数组，且第 2/4 组为放置位置 |
| 粗加工区放置 | 有环号字段和 `PLACE_RING` 动作 | 闭环缺失 | 未验证环号识别、环内判定、放置顺序和物料与地面接触判定 |
| 暂存区码垛 | 有第二批状态概念 | 缺失实机验证 | 规则要求第二批放在第一批对应物料上方；当前没有堆叠高度/姿态/掉落检测和码垛策略 |
| 完成后回启停区 | 有 `HOME`/`return_home` 动作 | 接口具备，未验证 | 没有底盘定位、回程路径和停止位置验收 |
| 一键启动 | 有 `start.sh`、桌面启动和自启动脚本 | 软件具备，实体要求未验证 | PDF 要求唯一、明确、不可遮挡的实体“启动”按钮；软件快捷方式不能代替实体按钮 |
| 禁止再次接触后的自主运行 | 有 live 模式入口 | 未验证 | 需要现场验证启动后不依赖键盘、鼠标、人工按空格或重新配置 |
| 15 秒无移动结束比赛 | 有通信/状态超时概念 | 缺失 | 没有以底盘运动反馈为依据的 15 秒无移动监控和安全结束策略 |

## 必须优先补齐的缺失项

1. **任务码模型改为正式规则格式**：四组三位数组，第一批搬运顺序、第一批放置位置、第二批搬运顺序、第二批放置位置；支持六种颜色映射，而不是当前默认两组和三种颜色。
2. **完成底盘运行闭环**：目标站点定位、里程计/位置反馈、车道约束、路径规划、到站停止和回启停区。
3. **接入实机传感器**：ToF/障碍物、限位、夹爪抓取确认、载荷掉落或到位确认；禁止用静态配置值代替传感器。
4. **完成抓取-放置-码垛状态闭环**：每件物料必须收到明确的抓取成功、放置完成和必要的掉落/位置结果，再允许下一件。
5. **修复 PackUnpack 应用层适配**：固定 10 字节帧只能承载 6 字节数据，当前 JSON 动作参数无法直接放入；需要与 F407 冻结命令字、数据字段、单位、序号和 ACK/DONE/FAIL 语义。
6. **增加物料形状和环位识别**：至少覆盖初赛回转体、六色物料和 1/2/3/4/5/6 环位置；为决赛形状变化保留可替换识别接口。
7. **实现任务码显示装置接口**：扫码后立即同步完整任务码，持续显示并验证字高、亮度、可读距离和断电/重启行为。
8. **实现比赛统计与人机显示**：显示任务码、当前批次、搬运顺序、放置位置、已完成数量、错误/重试、开始/结束时间和最终结果。
9. **落实无线通信要求**：确认使用 Wi-Fi、蓝牙或其他无线方式，并明确它是调试/状态上传还是比赛控制链路；比赛中不得依赖人工遥控。
10. **增加比赛约束监控**：15 秒无移动、越出车道、进入错误区域、物料掉落、启动后人工接触和危险状态。

## 必须现场验证的项目

### 视觉与扫码

- 六种颜色在实际光照、色差、反光、阴影和转盘旋转状态下的识别率。
- 二维码板 80×80 mm 在规定距离、角度和背景下的识别时间与重试策略。
- 任务码显示装置与扫码结果是否完全一致，能否清晰辨认。
- 物料被部分遮挡、相互靠近、旋转和批次交叠时的 ID 稳定性。
- 圆环 1～6 的数字识别、环内/环外判定和放置精度。
- 相机标定误差、地面坐标误差、旋转定位误差和重复定位误差。

### 机械和运动

- 从启停区到二维码板、原料区、粗加工区、暂存区的完整路径时间。
- 转盘 6～10 秒/转和停留位置误差下，目标是否可安全抓取。
- 物料抓取成功率、一次只抓一件、载运掉落率和夹爪确认延迟。
- 粗加工区按顺序放置、第二批物料在第一批上方码垛、物料接触地面后的完成判定。
- 回启停区的路线、停车位置和 15 秒无移动处理。
- 避障距离、急停、限位、ToF 误报/漏报、串口断开和 F407 重启恢复。

### 系统和比赛流程

- 一键启动后不触碰机器人即可完成整轮任务。
- 无网络或无线链路短暂中断时的安全行为；无线链路恢复后是否允许继续。
- 调试 3 分钟、任务抽签后 1 分钟更新、剩余 30 秒停止调试的现场流程。
- 不能更换零部件、不能人工整理物料、不能人工确认视觉项的比赛模式。
- 连续两轮任务码不同、颜色不同、放置位置不同的配置和运行日志隔离。
- 比赛结束后抓取/放置记录、结束时间、错误原因和最终统计是否可导出。

## 现场验收前的停止条件

以下任一项未通过时，不应把当前上位机标记为“智能搬运参赛版”：

- 四组三位任务码不能正确解析并驱动两批任务。
- 六种颜色或环号识别没有实际场地数据支持。
- 没有真实底盘定位、避障和路径规划闭环。
- 抓取确认、放置确认、码垛确认仍由静态配置或人工按键提供。
- PackUnpack 命令字段和 F407 固件未完成逐字节联调。
- 启动后仍需要键盘、鼠标或人工选择目标才能推进任务。
- 未验证 15 秒无移动、车道越界、物料掉落和通信断开时的安全行为。
