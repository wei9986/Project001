# 视觉模块深入开发指南

## 1. 开发原则

本文档用于指导视觉模块的二次开发、离线验证、实机联调和部署。

- 每个模块必须有明确的输入、输出和责任边界。
- 设备、算法、通信和任务逻辑必须解耦。
- 可调参数统一放入 `config/`，不要散落硬编码。
- 每个功能必须有正常、边界和故障测试。
- 关键行为必须写入结构化日志。
- 无实机时使用模拟设备和离线数据，不伪造硬件验证结果。

## 2. 系统分层

```text
设备层   摄像头、扫码器、串口、ToF、限位、抓取信号
感知层   颜色检测、目标跟踪、AprilTag、二维码、精定位
决策层   任务计划、任务状态机、安全状态机
通信层   STM32 协议、ACK、DONE、FAIL、重试、断线
运行层   app/运行循环.py、日志、配置、启动和监控
```

禁止越层调用：视觉不能直接控制电机，状态机不能直接读取 OpenCV 图像，串口不能判断物料是否抓取成功。

## 3. 统一运行层

文件：`app/运行循环.py`

运行流程：读取设备数据 -> 执行视觉算法 -> 生成感知结果 -> 读取传感器 -> 触发状态机事件 -> 执行通信动作 -> 写入日志。

开发要求：

- 固定运行周期，例如 20 ms、50 ms 或 100 ms。
- 每周期生成唯一 `cycle_id`。
- 运行层不实现颜色识别、不拼接通信帧。
- 设备通过接口或构造函数注入。
- 单个模块异常不能导致程序无日志退出。

建议统一输出 `RuntimeSnapshot`，包含 `cycle_id`、时间戳、相机状态、目标、工位、扫码结果、传感器、任务状态、通信状态和动作列表。

验收：正常任务完成；相机失败可进入故障；周期超时有日志；每个动作可追溯到输入事件。

## 4. 虚拟设备层

文件：`app/虚拟设备.py`

虚拟摄像头支持图片序列、视频、循环播放、读取失败、延迟、空帧和分辨率变化。虚拟扫码器支持正常任务码、无效 JSON、字段缺失、重复扫码、超时和错误物料码。虚拟传感器支持 ToF 正常距离、ToF 过近、限位触发、抓取成功、抓取失败和空数据。

验收：模拟接口与未来真实设备接口一致；测试不依赖摄像头和串口；可以切换输入场景。

## 5. 颜色检测和目标跟踪

文件：`vision/颜色追踪.py`；配置：`config/颜色追踪配置.json`。

开发顺序：HSV 分割、形态学处理、轮廓提取、面积过滤、圆度过滤、多目标匹配、目标确认、丢失处理、坐标转换、结果日志。

关键参数：`min_area`、`max_area`、`confirm_frames`、`max_match_distance`、`max_lost_frames`、`min_circularity`、`min_solidity`、HSV 范围和 ROI。

必须验证：噪声不能成为目标；未确认目标不能用于抓取；目标丢失不能使用旧坐标；多目标 ID 稳定；坐标跳变被拒绝；ROI 越界报错。

指标：检测准确率、漏检率、误检率、ID 切换次数、平均耗时和 P95 耗时。

## 6. 相机标定和坐标转换

文件：`vision/相机标定.py`。

开发内容：棋盘格内参、畸变校正、重投影误差、平面单应性、像素转场地坐标和标定文件版本检查。

人工验证：使用不同角度的多组棋盘格；检查重投影误差；在场地四角和中心放置已知点；比较实际坐标和计算坐标；验证分辨率变化。

验收：标定文件可读，分辨率匹配，坐标误差符合要求，损坏标定文件时拒绝启动。

## 7. AprilTag 工位识别

文件：`vision/站点定位.py`；配置：`config/站点标签.json`。

开发内容：Tag 字典、ID 到工位映射、中心点、角点排序、多 Tag、未知 ID、位姿估计和工位坐标转换。

必须验证：正常、旋转、倾斜、遮挡、过小、无 Tag、未知 ID、多 Tag 同时出现。

输出至少包含：`tag_id`、`station_id`、`center_px`、`corners_px`、`rvec`、`tvec`、`confidence`。

## 8. 精定位模块

文件：`vision/精定位.py`。

工作流程：粗定位 -> 目标筛选 -> 连续采样 -> 稳定性判断 -> 跳变拒绝 -> 平均坐标 -> 输出 `stable`。

开发重点：连续有效帧数、最大坐标跳变、离散范围、目标丢失超时、总超时和坐标滤波。只有输出 `stable` 时，状态机才允许抓取。

## 9. 扫码模块

文件：`mission/扫码读取.py`。

输入来源：USB 扫码器、TTL 扫码器、OpenCV 二维码和模拟扫码器。

任务码必须校验 `task_id`、`first_batch`、`second_batch`、`material_id`、`color`、`ring_code`。必须处理空字符串、非 JSON、类型错误、字段缺失、重复物料、未知颜色、未知环码和数量超限。

扫码模块只负责输入、解析和校验，不负责执行任务。

## 10. 任务计划和状态机

文件：`mission/任务计划.py`、`mission/任务状态机.py`。

正常流程：`S0_INIT -> S1_READ_TASK -> S2_FIRST_BATCH -> S3_PLACE_RING -> S4_SECOND_BATCH_ASSEMBLY -> S5_RETURN_HOME -> COMPLETE`。

开发原则：状态只能通过事件转换；转换必须记录；非法事件不能改变状态；每个状态有进入动作、退出条件和超时；异常进入恢复或安全停止。

每个状态至少测试正常进入、正常退出、非法事件、超时、通信失败、传感器失败、恢复成功和恢复失败。

## 11. 通信协议和传输层

文件：`protocol/串口协议.py`、`protocol/传输通道.py`。

分层结构：状态机动作 -> 协议消息类型 -> Frame 编码 -> `Transport.write` -> 串口或内存串口。

必须测试 ACK、DONE、FAIL、CRC 错误、半包、粘包、噪声、序号错误、版本错误、ACK 超时、DONE 超时、重试上限和心跳断开。

真实串口到位后只替换 `SerialTransport`，不修改协议编码器和任务状态机。

## 12. 虚拟 STM32 和故障注入

文件：`protocol/协议仿真.py`。

建议支持延迟响应、重复 ACK、错误序号、错误命令、执行中断、控制器复位、心跳停止、随机丢包和 CRC 损坏。

每种故障必须记录注入条件、预期状态、错误码、日志内容和恢复动作。

## 13. 安全策略

文件：`app/安全监控.py`。

安全状态建议：`正常 -> 警告 -> 恢复 -> 安全停止 -> 故障锁定`。

高优先级故障：限位触发、ToF 过近、串口断开、抓取失败、相机失联、坐标跳变和状态超时。

安全停止必须幂等、记录原因、禁止普通动作，并等待明确的恢复或复位事件。

## 14. 日志和监控

文件：`app/运行观测.py`。

建议日志：`vision.jsonl`、`mission.jsonl`、`protocol.jsonl`、`sensor.jsonl`、`runtime.status.jsonl`。

每条记录建议包含 `timestamp`、`cycle_id`、`module`、`state`、`event`、`action`、`error_code`、`latency_ms` 和 `payload`。

失败日志必须包含失败模块、当前状态、输入摘要、原因、重试次数和最终结果。

## 15. 离线回放和评测

文件：`tools/离线评测.py`。

场景：正常任务、多目标遮挡、亮度变化、图像模糊、错误工位、错误物料、重复扫码、抓取失败、传感器抖动、STM32 延迟、STM32 断线和运行超时。

报告至少包含场景名称、是否通过、最终状态、平均和最大循环时间、目标检测率、AprilTag 检测率、重试次数、恢复次数和错误码。

## 16. 配置和部署

文件：`tools/启动检查.py`、`requirements.txt`、`scripts/启动视觉仿真.sh`、`deploy/视觉模块仿真服务.service`。

检查 Python、OpenCV、NumPy、pyserial、配置文件、模型文件、日志目录、设备、权限和磁盘空间。

模拟检查：

```powershell
& '..\.venv\Scripts\python.exe' -m tools.启动检查 --json
& '..\.venv\Scripts\python.exe' -m app.视觉应用 --mode simulation
```

真实硬件检查：

```powershell
& '..\.venv\Scripts\python.exe' -m tools.启动检查 --require-hardware
```

## 17. 测试规范

测试文件：`tests/test_第二阶段流程.py`。

每个新功能至少增加一个正常测试、边界测试、非法输入测试、超时测试、恢复测试和日志测试。

完整验证：

```powershell
& '..\.venv\Scripts\python.exe' -m unittest discover -s tests -v
& '..\.venv\Scripts\python.exe' -m tools.离线评测
& '..\.venv\Scripts\python.exe' -m compileall -q app mission protocol vision tools tests
```

## 18. 数据集和人工验证

建议目录：`data/raw/`、`data/labeled/`、`data/replay/`、`data/calibration/`、`data/reports/`。

实机到位后采集正常光照、暗光、强光、反光、目标旋转、遮挡、多目标、AprilTag 倾斜、Tag 模糊、相机振动和背景接近目标等数据。

每组数据记录分辨率、距离、光照、相机参数和预期结果。

## 19. 二次开发流程

1. 明确输入和输出。
2. 增加配置参数。
3. 先增加失败测试。
4. 编写正式实现。
5. 增加正常测试。
6. 增加异常测试。
7. 运行完整回归测试。
8. 运行离线评测。
9. 检查日志和性能。
10. 接入运行时循环。

算法应先在对应的 `vision/`、`mission/` 或 `protocol/` 模块中独立验证，最后接入 `app/运行循环.py`。

## 20. 推荐开发顺序

```text
1. 完善 RuntimeSnapshot 统一感知结果
2. 增加真实图片和视频回放
3. 增加视觉准确率和坐标误差统计
4. 增强虚拟 STM32 故障注入
5. 完善安全状态机
6. 增加配置版本和类型校验
7. 增加资源和性能监控
8. 在树莓派上完成模拟部署
9. 接入真实相机
10. 接入真实扫码器、STM32 和传感器
```

实机到位前优先完成第 1～7 项。实机阶段主要替换设备适配器、校准参数并进行分层联调，不应重写核心任务流程。
